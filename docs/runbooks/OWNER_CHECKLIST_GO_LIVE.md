# Чек-лист запуска: ЮKassa и первые боевые платежи

**Для кого:** владелец / идеолог проекта (без программирования).  
**Зачем:** убедиться, что можно безопасно принять первые реальные деньги (пилот), а не только «код готов».  
**Админка-ориентир:** раздел **FinTech** → `/admin/settings/finances`.  
**Версия документа:** Stage **198** / Wave I.0 (2026-07-30).

> Код приёма через ЮKassa уже встроен. Этот чек-лист — **внешние** шаги и проверка «зелёных» индикаторов перед первыми ~100 ₽.

---

## Как пользоваться

1. Идите сверху вниз.  
2. Пункт закрыт — ставьте ☑.  
3. Красный или жёлтый в FinTech — **не** включайте боевой приём.  
4. Сначала **тестовый** магазин ЮKassa, потом боевой.

---

## 1. ЮKassa (личный кабинет)

### 1.1 Договор и доступ

| ☐ | Шаг |
|---|-----|
| ☐ | Заключён договор / магазин одобрен ЮKassa |
| ☐ | Есть вход в [личный кабинет ЮKassa](https://yookassa.ru/) |
| ☐ | Есть **тестовый** магазин (для проверки без настоящих денег) |
| ☐ | Позже: есть **боевой** (настоящий) магазин |

### 1.2 Идентификатор магазина (Shop ID)

| ☐ | Шаг |
|---|-----|
| ☐ | Откройте **Настройки → Магазин** |
| ☐ | Скопируйте **shopId** (идентификатор магазина) |
| ☐ | Передайте разработчику / положите в настройки сервера (production) как ключ магазина ЮKassa |

### 1.3 Секретный ключ (Secret Key)

| ☐ | Шаг |
|---|-----|
| ☐ | Откройте **Интеграция → Ключи API** |
| ☐ | Для **тестового** магазина ключ обычно уже виден в кабинете |
| ☐ | Для **боевого** магазина: создайте ключ → подтвердите SMS → **скачайте и сохраните** (повторно не показывают) |
| ☐ | Ключ **никому не публиковать** (чат, скриншоты, GitHub) |
| ☐ | Передайте разработчику для записи в защищённые переменные сервера |

### 1.4 Уведомления (Webhook) — обязательно

Без этого оплата на стороне ЮKassa может пройти, а бронь на сайте **не** перейдёт в «оплачено / эскроу».

| ☐ | Шаг |
|---|-----|
| ☐ | В кабинете ЮKassa откройте раздел **уведомлений / HTTP-уведомлений** (Integration / Notifications) |
| ☐ | Укажите адрес уведомлений (подставьте **ваш боевой домен**): |

```text
https://ВАШ-ДОМЕН/api/webhooks/payments/confirm
```

| ☐ | Включите минимум событие **успешной оплаты** (`payment.succeeded`) |
| ☐ | Рекомендуется также **отмена** (`payment.canceled`) — гость увидит понятный экран «оплата не прошла» |
| ☐ | Сохраните настройки |
| ☐ | Убедитесь, что разработчик включил проверку IP ЮKassa на production |

**Пример:** если сайт `https://airento.app`, адрес будет  
`https://airento.app/api/webhooks/payments/confirm`.

### 1.5 Проверка тестовой оплаты (до боевых денег)

| ☐ | Шаг |
|---|-----|
| ☐ | На тестовом магазине: создайте маленькую бронь → оплата **МИР** → редирект на ЮKassa |
| ☐ | Тестовая карта (из справки ЮKassa), например `5555555555554444` |
| ☐ | После возврата на сайт бронь стала **оплаченной** (эскроу) |
| ☐ | В FinTech виден тестовый платёж ЮKassa |

Только после этого — боевые ключи и пилот на ~100 ₽.

## 2. Онлайн-касса (54-ФЗ)

ЮKassa **принимает** деньги гостя. **Чек** по закону пробивает отдельная онлайн-касса (у вас — после успешной оплаты, на стороне платформы).

Без боевой кассы приём на production **блокируется** защитой сайта.

### 2.1 Что запросить у провайдера кассы

| ☐ | Запросить у провайдера |
|---|------------------------|
| ☐ | Адрес API кассы (это и есть **`FISCAL_PROVIDER_URL`** для сервера) |
| ☐ | Токен / логин / пароль или ключ API (как требует провайдер) |
| ☐ | ИНН и реквизиты продавца (ИП / юрлицо), которые уйдут в чек |
| ☐ | Подтверждение: **боевой** контур, не песочница |
| ☐ | Тестовый чек на 1 ₽ / минимальную сумму после первой оплаты |

### 2.2 Что сказать разработчику

| ☐ | Шаг |
|---|-----|
| ☐ | Передать URL кассы и секреты **только** в защищённые настройки сервера |
| ☐ | Песочница кассы на production **выключена** |
| ☐ | В FinTech пункт про кассу / fiscal — **зелёный** |

## 3. Юридический блок (должно быть открыто гостю)

На экране оплаты гость отмечает согласие. Ссылки должны открываться и быть актуальными.

| ☐ | Документ | Где смотреть на сайте |
|---|----------|------------------------|
| ☐ | **Публичная оферта** | `/legal/public-offer/` |
| ☐ | **Правила возврата** | `/legal/refund/` |
| ☐ | **Политика ПДн (конфиденциальность)** | `/legal/privacy/` |
| ☐ | Подсказка про эскроу / предоплату | `/help/escrow-protection` (и блок на checkout) |

| ☐ | Контроль |
|---|----------|
| ☐ | Документы опубликованы через админку юр. документов (`/admin/settings/legal`), версии не «черновик» |
| ☐ | На checkout видны ссылки на оферту и возврат; политика ПДн доступна с сайта |
| ☐ | Тексты согласованы с юристом / бухгалтером под вашу схему (РФ + платформа) |

## 4. Админка FinTech — «всё зелёное» перед первыми ~100 ₽

Откройте: **`/admin/settings/finances`**.

### 4.1 Карточки и индикаторы

| ☐ | Индикатор | Ожидание |
|---|-----------|----------|
| ☐ | **Pre-Live Readiness / Фаза 1** | Зелёный (защита кода: повтор webhook, эскроу, mock выкл) |
| ☐ | **Полный финансовый smoke** | Успешно пройден (все шаги OK) |
| ☐ | **Cron Health** | Задачи разморозки эскроу и подготовки выплат — не красные / не «протухшие» |
| ☐ | **ЮKassa Status** | Настроено: магазин виден, не «не сконфигурировано» |
| ☐ | **Касса (fiscal)** | Боевой URL задан, sandbox выкл |
| ☐ | **Emergency Pause** | **Выключен** (иначе гости не смогут платить) |
| ☐ | **Ручной Concierge / treasury** | Включён ручной режим выплат на старте (без автопулов) |
| ☐ | **Controlled Live** | Режим **ACTIVE** (пилот с лимитом) |
| ☐ | **Telegram FINANCE** | Бот и группа настроены; приходят тестовые алерты |

### 4.2 Controlled Live (пилот как у зрелых сервисов)

| ☐ | Шаг |
|---|-----|
| ☐ | Задан дневной лимит суммы пилотных броней (например через настройку лимита THB/день у разработчика) |
| ☐ | Нажато «Перейти в Live Mode» — виден баннер **CONTROLLED LIVE: ACTIVE** |
| ☐ | При первой боевой оплате ожидаете сообщение в Telegram FINANCE |
| ☐ | При приближении к дневному лимиту — предупреждение в Telegram (мягкий лимит) |

### 4.3 Первые ~100 ₽ (боевой пилот)

| ☐ | Шаг |
|---|-----|
| ☐ | Боевые ключи ЮKassa (не тестовые) |
| ☐ | Одна маленькая бронь, способ **МИР** |
| ☐ | Гость оплатил → вернулся на сайт → статус «оплачено / эскроу» |
| ☐ | Пришёл алерт в Telegram |
| ☐ | Чек кассы выпущен (или в очереди без ошибки) |
| ☐ | В FinTech платёж не помечен как `test` |

**Не расширяйте приём**, пока пилот не закрыт спокойно.

---

## 5. Краткий порядок «с нуля до первых денег»

1. Договор ЮKassa + тестовый магазин.  
2. Shop ID, секрет, webhook URL на ваш домен.  
3. Боевая онлайн-касса + юр. страницы.  
4. FinTech: всё зелёное + Controlled Live ACTIVE.  
5. Тестовая оплата → затем одна боевая ~100 ₽.  
6. Только потом — больше гостей.

---

## 6. Если что-то пошло не так

| Симптом | Что проверить |
|---------|----------------|
| Гость оплатил в ЮKassa, на сайте «не оплачено» | Webhook URL, события, IP, логи FinTech / Telegram |
| Кнопка оплаты недоступна / ошибка кассы | Касса URL, sandbox выкл, Emergency Pause |
| Нет алертов | Telegram FINANCE: токен бота и ID группы |
| Деньги зависли у партнёра | Cron Health + ручной Concierge (это нормально на старте) |

Подробные технические runbook’и для команды: `docs/GO_NO_GO_FIRST_REAL_PAYMENT.md`, `docs/PRE_REAL_PAYMENTS_CHECKLIST.md`, `docs/CONTROLLED_LIVE_RUNBOOK.md`.
